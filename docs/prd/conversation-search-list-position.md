# PRD：会话搜索后左侧会话列表同步定位

- 状态：Draft v0.1
- 关联 Issue：https://github.com/CiccyZ/octo-cli-agent-demand-pool-zx/issues/8
- 类型：Feature / UX
- 优先级：P2
- 模块：Agent 自动化模块 / 会话页面
- 来源：Octo 群用户反馈

## 1. 背景

用户反馈：在会话页面搜索联系人时，右边的聊天窗口会切换成目标联系人，但左边的会话列表没有定位，希望优化这个体验。

该问题影响的是用户在搜索进入会话后的上下文确认。用户通过搜索快速进入某个联系人聊天后，仍需要知道当前会话在左侧列表中的位置，方便继续浏览、切换、确认选中状态或回到列表上下文。

## 2. 用户问题

当用户在会话页面搜索联系人并进入目标聊天后，右侧聊天窗口已经显示目标联系人，但左侧会话列表没有同步定位到对应会话。用户无法从左侧列表确认当前会话对应哪一项，容易产生“右侧已切换、左侧仍停留在别处”的割裂感。

## 3. 目标用户

- 经常在会话页面通过搜索查找联系人并进入聊天的用户。
- 会话列表较长、需要频繁切换联系人或群聊的用户。
- 需要通过左侧会话列表确认当前聊天上下文的用户。

## 4. 用户故事

作为一个在会话页面搜索联系人进入聊天的用户，
我希望右侧聊天窗口切换到目标联系人时，左侧会话列表也同步定位并高亮该会话，
以便我能明确知道当前聊天在会话列表中的位置。

## 5. 需求范围

范围内：

- 用户在会话页面搜索联系人并选择目标后，右侧聊天窗口切换到目标会话。
- 左侧会话列表需要同步定位到目标会话。
- 如果目标会话不在左侧列表当前可见区域，应让该会话进入可见区域。
- 目标会话需要有清晰的选中或高亮状态。
- 用户应能通过左侧列表确认当前右侧聊天窗口对应哪个会话。

## 6. 非目标

本需求不包含：

- 不改变搜索结果的排序规则。
- 不新增联系人搜索范围、筛选条件或高级搜索能力。
- 不改变会话列表本身的排序规则。
- 不改变会话消息内容区的展示规则。
- 不改变会话创建、删除、归档、置顶等能力。
- 不承诺具体技术实现方式。

## 7. 体验要求

- 搜索并进入目标联系人后，用户不需要手动在左侧列表中再次查找该会话。
- 左侧定位应让用户自然感知当前会话所在位置，而不是只依赖右侧聊天标题判断。
- 当目标会话在列表中不可见时，应进入可见区域，避免用户误以为左侧列表没有切换。
- 选中/高亮状态应清晰，但不应干扰未读、置顶、免打扰等已有状态识别。
- 如果用户后续手动滚动或切换其他会话，现有交互应保持稳定。

## 8. 验收标准

1. 用户在会话页面搜索联系人并选择目标后，右侧聊天窗口切换到目标联系人。
2. 左侧会话列表同步定位到该联系人对应会话。
3. 如果目标会话不在左侧列表当前可见区域，列表应让该会话进入可见区域。
4. 目标会话在左侧列表中有清晰选中或高亮状态，用户能确认当前聊天对应哪一项。
5. 用户继续手动滚动会话列表、切换其他会话、再次搜索其他联系人时，现有操作不受影响。
6. 未读、置顶、免打扰、Bot 对话、群聊等已有状态在定位和高亮后仍清晰可识别。

## 9. 风险与待确认问题

- 需要确认该会话页面是否同时覆盖 Web、macOS、移动端或其他客户端形态。
- 需要确认搜索联系人进入聊天时，如果该联系人尚未出现在左侧会话列表中，产品应创建/插入会话，还是只切换右侧窗口。
- 需要确认目标会话被置顶、归档、隐藏或处于特殊分组时，左侧定位应如何表现。
- 需要确认左侧会话列表是否存在虚拟滚动、分页或分组展示；用户可见效果仍应以“定位到目标会话”为准。
