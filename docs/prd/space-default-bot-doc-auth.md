# PRD：Space 级默认授权 Bot 访问新文档

- 状态：Draft v0.2（已按 PRD Review 补齐权限边界）
- 关联 Issue：https://github.com/CiccyZ/octo-cli-agent-demand-pool-zx/issues/3
- 类型：Feature
- 优先级：P2
- 模块：文档权限模块
- 来源：Octo 群用户反馈

## 1. 背景

用户在 Space 中使用 Bot 处理文档时，希望减少每份新文档都要单独分享给 Bot 的重复操作。

当前用户诉求是：能否在 Space 级别默认授权给某个 Bot，使该 Space 后续新建文档自动让该 Bot 具备访问权限。

## 2. 用户问题

当 Space 中持续产生新文档时，用户需要逐份手动分享给 Bot。这个过程重复、容易遗漏，也会导致 Bot 在处理新文档时因为没有权限而无法访问。

## 3. 目标用户

- 在 Space 中持续创建或协作文档的用户。
- 需要 Bot 长期读取、总结、分析或处理 Space 文档的用户。
- 管理一个团队 Space，并希望统一配置 Bot 文档访问规则的 Space 所有者或具备权限管理能力的 Space 管理员。

## 4. 用户故事

作为 Space 所有者或具备权限管理能力的 Space 管理员，
我希望可以在 Space 级别给指定 Bot 配置默认只读文档访问权限，
以便后续新建文档自动让该 Bot 可访问，不需要每份文档重复手动分享。

## 5. 需求范围

范围内：

- Space 所有者或具备权限管理能力的 Space 管理员可以为某个 Space 配置指定 Bot 的默认文档访问权限。
- 默认授权仅覆盖该 Space 中后续新建的在线文档。
- 用户能看清哪些 Bot 拥有 Space 级默认文档权限。
- 用户能撤销指定 Bot 的默认权限；本期默认权限档位固定为只读，不支持配置评论或编辑权限。
- 当默认权限生效后，用户新建文档时不需要再逐份分享给该 Bot。
- 默认授权只对新文档生效，需要在产品界面或说明中明确提示。

## 6. 非目标

本需求不包含：

- 不自动改变所有历史文档权限；历史文档批量补授权不属于本期范围。
- 不定义具体技术实现方式。
- 不改变普通用户对单篇文档的手动分享能力。
- 不改变非文档类资源的权限规则；本期仅覆盖 Space 内后续新建的在线文档。
- 不承诺所有 Bot 默认拥有权限，默认授权只能由 Space 所有者或具备权限管理能力的 Space 管理员主动配置。

## 7. 体验要求

- 配置入口应让用户理解这是 Space 级默认文档授权，不是单篇文档分享。
- 用户需要能明确看到授权对象是哪个 Bot。
- 用户需要能明确看到默认权限适用范围：本期为“仅后续新建在线文档”。
- 撤销默认授权后，用户应能理解撤销仅影响后续新建文档，不自动回收历史已授权文档的访问权限。
- 当 Bot 因缺少权限无法访问文档时，用户应能获得清楚提示，而不是只看到失败。

## 8. 验收标准

1. Space 所有者或具备权限管理能力的 Space 管理员可以为指定 Bot 配置默认文档访问权限。
2. 配置成功后，用户能在 Space 权限或 Bot 授权相关入口看到该 Bot 的默认授权状态。
3. 配置生效后，该 Space 下后续新建的在线文档自动让该 Bot 具备只读访问权限。
4. 用户新建文档后，不需要再逐份手动分享给该 Bot，Bot 即可访问该新文档。
5. Space 所有者或具备权限管理能力的 Space 管理员可以撤销该 Bot 的默认授权。
6. 默认授权的适用范围清晰可见，用户能知道本期仅影响后续新建在线文档，不自动影响历史文档。
7. 当 Bot 没有访问权限时，用户能看到清楚的权限缺失提示和下一步处理建议。
8. 权限变更不会让未被授权的 Bot 获得访问能力；评论、编辑等更高权限不会因本默认规则自动授予。

## 9. 风险与待确认问题

- 本期口径已收敛为仅覆盖后续新建在线文档；历史文档批量补授权如需支持，应另起需求评估。
- 本期口径已收敛为默认只读权限；评论、编辑权限如需支持，应另起需求或作为后续版本评估。
- 本期配置主体限定为 Space 所有者或具备权限管理能力的 Space 管理员；需要产品确认现有角色命名和 UI 文案。
- 需要确认“在线文档”的产品边界名称是否与现有 Docs / html / Drive-mounted docs 一致，并在 UI/API/CLI 文档中使用统一表述。
- 撤销默认授权本期仅影响后续新建文档，不自动回收历史已授权文档；需要在撤销确认弹窗或说明中清晰提示。
