# PRD：Web/macOS 1.0.12 收到消息显示异常修复

- 状态：Draft v0.1
- 关联 Issue：https://github.com/CiccyZ/octo-cli-agent-demand-pool-zx/issues/5
- 类型：Bug
- 优先级：P1
- 模块：Agent 自动化模块 / 消息展示
- 来源：Octo 群用户反馈

## 1. 背景

用户反馈：Web · macOS 当前版本 1.0.12 中，别人发消息后，用户这边显示异常。

消息展示是对话产品的核心体验。如果用户收到消息后无法正常阅读，会直接影响沟通、任务协作和对系统可靠性的信任。

## 2. 用户问题

在 Web/macOS 1.0.12 中，用户接收他人消息时，消息在本机展示异常。当前反馈尚未补充具体异常形态，可能表现为内容不可读、错位、重复、顺序异常或其他显示问题，需要后续补充截图或录屏确认。

## 3. 目标用户

- 使用 Web/macOS 客户端接收消息的用户。
- 需要稳定查看私聊、群聊或工作消息的用户。
- 依赖消息列表进行任务沟通和信息确认的用户。

## 4. 用户故事

作为 Web/macOS 客户端用户，
我希望别人发来的消息能够稳定、清晰、按正确顺序显示，
以便我不需要刷新、重启或切换设备，也能正常阅读和处理消息。

## 5. 需求范围

范围内：

- 修复 Web/macOS 1.0.12 中接收他人消息后显示异常的问题。
- 收到消息后，消息内容、发送人、时间、顺序和基础样式应清晰可读。
- 如果异常与特定消息类型有关，需要保证该类型消息也能正常展示。
- 用户不应依赖刷新、重启或切换设备来恢复正常显示。
- 如果问题无法复现，需要补充可定位的信息收集和用户提示。

## 6. 非目标

本需求不包含：

- 不重新设计消息列表整体视觉风格。
- 不新增消息搜索、筛选、排序能力。
- 不改变消息发送流程或发送规则。
- 不承诺具体技术实现方式。
- 不解决与本问题无关的网络延迟或通知推送问题，除非确认与显示异常有关。

## 7. 体验要求

- 用户收到新消息后，应能直接看懂消息内容。
- 消息展示不应出现明显错位、乱码、重复、缺失或顺序混乱。
- 如果消息暂时无法展示，用户应看到清楚、可理解的提示，而不是异常空白或错乱界面。
- 修复不应影响用户查看历史消息或发送新消息。

## 8. 验收标准

1. 在 Web/macOS 客户端中，用户收到他人发送的普通文本消息后，消息内容正常显示。
2. 收到消息后，发送人、消息时间、消息顺序和基础样式均清晰可读。
3. 用户不需要刷新页面、重启客户端或切换设备，也能看到正常消息展示。
4. 如果异常与特定消息类型有关，修复后该类型消息在私聊和群聊中均可正常展示。
5. 连续收到多条消息时，消息顺序对用户可理解，不出现明显错乱或重复展示。
6. 修复后，用户查看历史消息和发送新消息的体验不受影响。
7. 回归验证中至少覆盖一次“他人发送消息 → 本机正常展示”的完整用户路径。

## 9. 风险与待确认问题

- 需要补充异常截图、录屏或更具体的问题表现。
- 需要确认异常是否只发生在 Web/macOS 1.0.12，还是其他平台或版本也存在。
- 需要确认异常是否只影响特定消息类型。
- 需要确认异常是否与会话类型相关，例如私聊、群聊、Thread 或 Bot 消息。
- 需要确认用户是否需要临时绕过建议，例如刷新、重启或切换客户端；该建议只能作为临时措施，不是验收完成标准。
