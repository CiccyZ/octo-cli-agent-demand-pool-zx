# PRD：Windows 支持通过 winget 安装 octo-cli

- 状态：Draft v0.1
- 关联 Issue：https://github.com/CiccyZ/octo-cli-agent-demand-pool-zx/issues/9
- 类型：Feature
- 优先级：P2
- 模块：octo-cli 安装 / 分发 / Windows 部署体验
- 来源：Octo 群用户反馈（AINOL考官转述李明反馈）

## 1. 背景

用户反馈：希望 `octo-cli` 能支持通过 `winget` 安装。反馈场景是团队里 Windows 机器较多，目前只能手动下载 `tar.gz` 并解压，安装和维护比较麻烦。

该问题影响的是 Windows 用户的首次安装、批量部署和后续维护体验。对于 Windows 机器较多的团队，手动下载安装包、解压、配置和更新的成本会随着机器数量增加而放大。

## 2. 用户问题

Windows 用户当前无法通过常用的 `winget` 方式直接安装 `octo-cli`，需要手动下载 `tar.gz` 后解压。这个流程对单台机器可以接受，但在多台 Windows 机器上重复执行时效率低、容易出错，也不利于统一升级和卸载。

## 3. 目标用户

- 在 Windows 环境使用 `octo-cli` 的个人用户。
- 需要在多台 Windows 机器上安装或维护 `octo-cli` 的团队用户。
- 习惯使用 Windows 包管理工具安装 CLI 工具的用户。

## 4. 用户故事

作为一个 Windows 用户，
我希望可以通过 `winget` 安装 `octo-cli`，
以便我不用手动下载和解压安装包，也能更方便地升级和卸载。

作为一个负责多台 Windows 机器工具部署的团队成员，
我希望 `octo-cli` 支持标准化的 Windows 安装入口，
以便我能降低重复部署和维护成本。

## 5. 需求范围

范围内：

- Windows 用户可以通过 `winget` 搜索到 `octo-cli`。
- Windows 用户可以通过 `winget` 完成 `octo-cli` 安装。
- 安装完成后，用户可以在命令行中直接执行 `octo-cli` 并看到正常命令响应。
- Windows 用户可以通过 `winget` 完成 `octo-cli` 升级或卸载。
- 安装文档需要补充 `winget` 安装方式，并说明适用平台、前置条件和常见失败处理建议。

## 6. 非目标

本需求不包含：

- 不改变 `octo-cli` 现有 tar.gz 下载方式。
- 不要求移除或替换现有安装文档中的其他安装路径。
- 不覆盖 Windows 以外平台的包管理器支持。
- 不承诺企业内部统一软件分发平台的集成。
- 不承诺具体技术实现方式。

## 7. 体验要求

- Windows 用户能用接近系统常规软件安装的方式获取 `octo-cli`。
- 安装流程应尽量减少手动下载、解压、移动文件、配置路径等步骤。
- 安装成功后，用户能明确知道下一步如何验证 `octo-cli` 可用。
- 安装失败时，文档应提供用户能理解的排查方向，例如前置条件不满足、网络不可达、包未检索到等。
- 升级和卸载路径应清晰，避免用户只能重新下载压缩包覆盖旧版本。

## 8. 验收标准

1. Windows 用户可以通过 `winget` 搜索到 `octo-cli`。
2. Windows 用户可以通过 `winget` 完成 `octo-cli` 安装。
3. 安装完成后，用户打开命令行执行 `octo-cli`，可以看到正常命令响应或帮助信息。
4. Windows 用户可以通过 `winget` 完成 `octo-cli` 升级。
5. Windows 用户可以通过 `winget` 完成 `octo-cli` 卸载。
6. 安装文档包含 `winget` 安装方式、适用平台、前置条件和常见失败处理建议。
7. 现有 tar.gz 下载和手动安装路径仍可继续使用，已依赖现有方式的用户不受影响。

## 9. 风险与待确认问题

- 需要确认 `octo-cli` 当前 Windows 发行包形态是否适合直接面向 `winget` 用户使用。
- 需要确认 Windows 支持范围，例如 Windows 版本、CPU 架构、PowerShell / CMD 使用差异。
- 需要确认 `winget` 包名、展示名称、描述和发布节奏的产品口径。
- 需要确认安装后命令是否需要额外配置环境变量；从用户视角应尽量做到安装后可直接执行。
- 需要确认企业内网环境是否能访问公开 `winget` 源；如果不能，是否需要另行规划内网分发方案。
