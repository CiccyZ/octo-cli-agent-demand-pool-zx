# PRD：Loop 已完成任务按完成时间倒序展示

- 状态：Draft v0.2（已按 PRD Review 补齐排序口径）
- 关联 Issue：https://github.com/CiccyZ/octo-cli-agent-demand-pool-zx/issues/4
- 类型：Feature / UX
- 优先级：P2
- 模块：任务协作模块
- 来源：Octo 群用户反馈

## 1. 背景

用户反馈：Loop 任务里的“已完成”列表顺序打乱，任务多时需要反复翻找，希望已完成任务能按完成时间排序，最新完成的放在最上面。

该问题影响的是用户回看近期完成事项的效率。已完成任务通常用于确认刚处理完的工作、追踪最近交付内容或快速复盘；如果顺序不清晰，用户需要额外查找。

## 2. 用户问题

当“已完成”任务较多时，列表没有按照用户预期的完成时间从新到旧展示，导致最近完成的任务不容易被快速找到。

## 3. 目标用户

- 使用 Loop 管理任务的用户。
- 需要频繁查看已完成任务的项目成员。
- 需要追踪近期完成事项、复盘或确认交付状态的用户。

## 4. 用户故事

作为一个使用 Loop 管理事项的用户，
我希望“已完成”任务默认按最近一次完成时间从新到旧排列，
以便我能最快找到最近完成的任务。

## 5. 需求范围

范围内：

- “已完成”任务列表默认按完成时间倒序展示。
- “完成时间”定义为任务最近一次从未完成状态变为已完成状态的时间。
- 最新完成的任务显示在最上方。
- 任务被重新打开后再次完成时，按再次完成的时间重新进入已完成列表排序。
- 完成时间相同或缺少完成时间时，列表仍应保持稳定顺序，避免刷新后跳动。
- 缺少完成时间的历史任务展示在有完成时间的任务之后；缺失组内部沿用原有稳定展示顺序，不因刷新随机变化。
- 排序规则应让用户容易理解，例如“最近完成优先”。
- 如果产品提供排序选项，用户切换后应能明确知道当前排序方式。

## 6. 非目标

本需求不包含：

- 不改变未完成任务列表的排序规则。
- 不改变任务完成、取消完成、重新打开等核心状态流转，只定义这些状态变化后在“已完成”列表里的展示顺序。
- 不新增复杂筛选、搜索或分组能力。
- 不承诺具体技术实现方式。
- 不改变任务详情页内容结构。

## 7. 体验要求

- 用户进入“已完成”列表后，首先看到最近完成的任务。
- 用户不需要手动切换或理解复杂规则，就能按直觉查看近期完成事项。
- 如果存在缺少完成时间的历史任务，展示顺序不能显得随机。
- 当任务完成状态发生变化后，用户再次查看已完成列表时，列表位置应符合“最近一次完成优先”的预期。
- 历史任务如果缺少完成时间，应整体位于有完成时间任务之后，并保持稳定展示，不因为刷新、切换列表或重新进入页面而随机跳动。

## 8. 验收标准

1. 用户打开 Loop 的“已完成”任务列表时，最近一次完成的任务显示在最上方。
2. 多个已完成任务按最近一次完成时间从新到旧排列。
3. 一个已完成任务被重新打开后再次标记完成时，应按再次完成的时间重新排序到对应位置。
4. 当两个任务完成时间相同或部分任务缺少完成时间时，列表仍保持稳定展示，刷新后不会随机跳动。
5. 缺少完成时间的历史任务展示在有完成时间的任务之后，且缺失组内部沿用原有稳定展示顺序。
6. 未完成任务列表的现有展示规则不受影响。
7. 用户将一个任务标记为完成后，再进入“已完成”列表，可以在靠前位置看到该任务。
8. 当已完成任务数量较多时，用户能比原先更快找到最近完成的任务。
9. 如果提供排序选项，当前排序方式对用户可见，并且默认仍为最近完成优先。

## 9. 风险与待确认问题

- 本期口径已定义：“完成时间”指任务最近一次从未完成状态变为已完成状态的时间。
- 本期口径已定义：重新打开后再次完成的任务，按再次完成时间排序。
- 本期口径已定义：缺少完成时间的历史任务展示在有完成时间任务之后，缺失组内部保持原有稳定顺序。
- 需要确认是否所有平台或客户端都需要保持同样排序体验。
- 需要确认是否需要给用户提供额外排序选项，还是只调整默认排序。
