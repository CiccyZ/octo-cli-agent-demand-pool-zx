# PRD：对话选择栏条目区隔优化

- 状态：Draft v0.1
- 关联 Issue：https://github.com/CiccyZ/octo-cli-agent-demand-pool-zx/issues/6
- 类型：UX / 体验优化
- 优先级：P2
- 模块：Agent 自动化模块 / 对话选择栏
- 来源：Octo 群用户反馈

## 1. 背景

用户反馈：在对话选择栏中，多个对话之间没有比较明显的分割线。当对话数量较多时，用户不容易快速找到要找的对话。

该问题影响的是对话列表的浏览和定位效率。用户在多会话场景下，需要依靠对话条目的边界、层级和状态差异来快速扫视列表；如果条目之间区隔不明显，会增加查找成本。

## 2. 用户问题

当对话选择栏里出现较多对话时，不同对话条目之间的视觉边界不够明显，用户容易看串行或需要反复停顿确认，导致目标对话不容易被快速定位。

## 3. 目标用户

- 同时拥有多个对话的用户。
- 需要频繁在不同对话之间切换的用户。
- 在较长对话列表中查找指定联系人、群聊或任务上下文的用户。

## 4. 用户故事

作为一个经常切换多个对话的用户，
我希望对话选择栏里的每个对话条目都有清晰区隔，
以便在对话数量较多时，也能快速找到目标对话并进入。

## 5. 需求范围

本需求关注对话选择栏中“对话条目之间的可区分性”。

范围内：

- 对话条目之间需要有更清晰的视觉区隔。
- 当前选中对话需要和普通对话明显区分。
- 鼠标悬停或聚焦时，需要让用户明确知道当前指向的是哪一个对话。
- 未读、置顶、活跃对话等状态不能因为区隔优化而变得不清楚。
- 当对话数量较多、列表需要滚动时，条目边界仍应清晰可辨。

## 6. 非目标

本需求不包含：

- 不调整对话排序规则。
- 不新增搜索、筛选、分组等查找能力。
- 不改变对话消息内容区的展示规则。
- 不改变会话创建、删除、归档等行为。
- 不承诺具体视觉实现方式，由设计和研发在不影响整体风格的前提下确定。

## 7. 体验要求

- 用户应能一眼看出一个对话条目的开始和结束。
- 当前选中的对话应有清晰状态，避免用户误判当前所在会话。
- 悬停或键盘聚焦时，应能明确提示当前将要打开的对话。
- 视觉区隔不能过重，避免列表变得嘈杂或影响阅读。
- 对话标题、头像、最近消息、时间、未读提示等信息仍需保持清晰。

## 8. 验收标准

1. 当对话选择栏中有 20 个及以上对话时，用户能明显区分相邻对话条目的边界。
2. 用户滚动浏览较长对话列表时，不需要反复停顿确认条目范围，也能快速定位目标对话。
3. 当前选中对话与普通对话有清晰差异，用户能立即判断自己当前所在会话。
4. 鼠标悬停或键盘聚焦到某个对话时，用户能明确感知当前指向的是哪一个对话。
5. 未读、置顶、活跃等已有状态仍然清晰可见，不会被新的区隔样式削弱。
6. 优化后不影响对话标题、头像、最近消息、时间等信息的可读性。
7. 在浅色/深色主题（如产品支持）下，对话条目区隔都应清晰可见。

## 9. 风险与待确认问题

- 需要确认当前产品是否同时支持浅色/深色主题；如果支持，两种主题都要验收。
- 需要确认对话选择栏是否存在移动端或窄屏形态；如果存在，需要同步考虑小屏幕可读性。
- 需要确认是否有置顶、未读、免打扰、Bot 对话、群聊等特殊状态；区隔优化不能影响这些状态识别。
- 需要设计确认最终视觉方案，避免分割过重导致列表噪音增加。
